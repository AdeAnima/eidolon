# eidolon-image

Report-only still-image near-duplicate detection. Input files are opened for reading only. The crate neither moves nor rewrites them.

## Public API

- `decode(&Path) -> anyhow::Result<image::DynamicImage>`: JPEG, PNG, WebP, GIF (first image), TIFF, BMP, HEIC/HEIF; content sniffing and EXIF orientation. HEIF primary-item `irot`/`imir` transforms take precedence over redundant EXIF, avoiding double rotation. Decoder-provided bit depth/alpha are retained; comparison previews are normalized separately.
- `find(&[FileEntry], &Ctx, Option<&HashMap<FileId, Vec<f32>>>) -> anyhow::Result<Vec<Match>>`: sorted near matches with evidence and `min_score` filtering. The optional borrowed bank comes from `source_frame_embeddings`; its source-aspect center-crop cosine neighbors supplement rather than displace whole-image candidates. The CLI supplies this bank when `--image-source-bank on` (the default) and embeddings are enabled, independently of thumbnail matching. `--image-source-bank off` passes no bank; disabled embeddings ignore any supplied bank. Both modes require pixel proof; `config.fast` uses distributed thumbnail samples. Non-directional IDs are ascending; `CropOf.a` is the part, independent of input order or resolution.
- `embed::OnnxEmbedder::load(&Path) -> anyhow::Result<Option<OnnxEmbedder>>`: verifies and retains the pinned graph without initializing ONNX Runtime or sessions. `load_with_device(&Path, ExecutionDevice)` explicitly chooses `Auto`, `Cpu`, or `CoreMl`; `set_workload(usize)` supplies the uncached-work estimate for Auto. `device()` reports the plan before inference and the actual provider afterward. Missing models return `None`; invalid models are errors. Runtime/provider errors occur at `Embedder::prepare()` or the first embedding.
- `models::fetch(&Path) -> anyhow::Result<()>`: explicit, streaming model download with SHA-256 verification and atomic publication. Existing corrupt models are rejected, not silently overwritten.
- `uncached_embedding_work(&[FileEntry], &Ctx, bool) -> anyhow::Result<usize>`: counts fresh whole-image embedding cache misses without decoding inputs or initializing inference, including equivalent provider-qualified Auto cache hits. The boolean also includes source-center cache misses; the CLI follows `--image-source-bank` (default `on`) and excludes that work when `off`.
- `source_frame_embeddings(&[FileEntry], &Ctx) -> anyhow::Result<HashMap<FileId, Vec<f32>>>`: loads or computes normalized source-aspect center descriptors using the retrieval decoder and frame preprocessing. Its independent cache identity includes the input decoder, preprocessing, and resolved provider. With `--image-source-bank on`, the CLI calls it for image-only and mixed-media scans, independently of thumbnail matching; `off` skips preparation. Recoverable decode failures are omitted here and reported by `find`; cache/model failures remain fatal.

The caller owns the cache/config/embedder. A dedicated Rayon pool respects `config.jobs` (zero means available CPUs). OpenCV's native workers are limited to one to avoid nested oversubscription of this pool. ONNX CPU inference shares a bounded session pool across stills and video frames; callers reserve an idle session rather than serializing on one session. ONNX Runtime telemetry is explicitly disabled. Scans are offline; `models::fetch` is the only network entry point.

## Model and native dependencies

Homebrew: `brew install libheif jpeg-turbo opencv onnxruntime pkgconf llvm`. `turbojpeg` 1.5.1 (MIT/Unlicense) uses the installed libjpeg-turbo through `pkg-config`; native libraries are not built or downloaded. `fast_image_resize` 6.1.0 (MIT/Apache-2.0) supplies SIMD retrieval resizing. macOS uses `objc2-image-io`, `objc2-core-graphics`, and `objc2-core-foundation` 0.3.2 (MIT/Zlib/Apache-2.0) with the system ImageIO/CoreGraphics frameworks for HEIF retrieval previews; no Apple framework is downloaded. OpenCV **5** uses the `features`/`geometry` Rust modules; `opencv` 0.101.1 supports the installed headers. `ort` uses `load-dynamic` without build-time binary downloads. Before any session is created, the crate explicitly loads `ORT_DYLIB_PATH` when set, otherwise its build-recorded `EIDOLON_ORT_DYLIB_PATH`. On macOS, `build.rs` detects `brew --prefix onnxruntime` unless the build variable is supplied explicitly. Missing libraries return an actionable error naming `ORT_DYLIB_PATH` rather than entering ort's implicit loader. Standalone binaries do not rely on Cargo injecting environment variables. Override `LIBCLANG_PATH` with `$(brew --prefix llvm)/lib` for Homebrew builds.

The native TurboJPEG API library is covered by the IJG and BSD-3-Clause licences. Decoder/resizer/binding dependencies contain no telemetry; ONNX Runtime telemetry is disabled explicitly.

The default model is the CPU-compatible FP32 ONNX conversion of DINOv2-small:

- Source: [onnx-community/dinov2-small](https://huggingface.co/onnx-community/dinov2-small/tree/8b1f705a3a7f6f062f6bdd21986c1583d3ef105d), based on [facebook/dinov2-small](https://huggingface.co/facebook/dinov2-small).
- Revision: `8b1f705a3a7f6f062f6bdd21986c1583d3ef105d`, `onnx/model.onnx`, 88,532,934 bytes; local filename `dinov2-small.onnx`.
- SHA-256: `f22797eabf810a75e41de68d378541ebea372122b25c4ce3ef25ff618250c20a` (upstream Git LFS object ID).
- ImageNet mean/std, CHW floats, and normalized 384-dimensional CLS output follow the [pinned model configuration](https://huggingface.co/onnx-community/dinov2-small/blob/8b1f705a3a7f6f062f6bdd21986c1583d3ef105d/preprocessor_config.json). Still-image matching replaces its center crop with a Catmull–Rom resize of the **entire image to 224×224**: aspect ratio is squashed, with no crop or padding, retaining off-center content. Video and `FrameOf` matching keep the original center-square crop, resize to 256, and center crop to 224 on both sides of each comparison. Both policies share the same verified graph and inference sessions.

Checksum validation also happens at load, not just fetch. The model identity and preprocessing version are part of embedding cache keys.

### Embedding execution devices

`ExecutionDevice::{Auto, Cpu, CoreMl}` selects the local inference policy. `OnnxEmbedder::load` delegates to `load_with_device(..., Auto)`. The CLI counts uncached work once before starting detectors: each image contributes one whole-image miss and, with `--image-source-bank on`, one independent source-aspect center miss; dispatched video misses contribute an upper bound of the configured maximum frame count (or retained remote samples); enabled mixed-media thumbnail matching adds one image-to-video descriptor miss per image independently of the source-bank option. Auto chooses CPU for at most 2,193 uncached embeddings and CoreML above that bound on supported Apple platforms. The conservative crossover uses measured retained-package startup (29.891 s CoreML versus 0.302 s CPU) and 16-caller throughput (250.996 versus 57.206 embeddings/s): `ceil((29.891 - 0.302) / (1 / 57.206 - 1 / 250.996))`. It is a machine-derived heuristic, not a guarantee for other hardware or caller counts; video bounds can overestimate inference work. Library callers without a workload estimate default to CPU. If CoreML registration, cache preparation, or compilation fails, Auto retries CPU with one stderr warning. Unsupported platforms select CPU directly. Explicit provider requests are unchanged.

Both model loading methods only retain the verified 84.4 MiB graph snapshot. Runtime loading and the first session happen only after a cache miss requires inference. A completely cached scan creates no ONNX sessions, including when the compiled CoreML package is missing. `Embedder::prepare()` has a default no-op implementation for injected embedders; detectors call it only on misses, then obtain the resolved model identity again for writes.

CPU explicitly registers the device named `CPUExecutionProvider` through ORT's device API and disables inherited environment providers. This applies to explicit CPU requests and automatic CPU fallback. `ort` rc.12 otherwise enables automatic EP selection, which can register CoreML even when no accelerator was requested. A CPU-type preference alone is insufficient: [ORT's policy selects the first CPU-type EP](https://github.com/microsoft/onnxruntime/blob/v1.31.1/onnxruntime/core/session/provider_policy_context.cc), not necessarily the built-in CPU provider. The native regression observed 375 CPU kernel events and no other providers for both CPU paths.

CoreML uses one MLProgram session with `MLComputeUnits=ALL`, allowing Apple to select CPU, GPU, or ANE. Its inputs are fixed to `[1, 3, 224, 224]` through ONNX Runtime's symbolic-dimension overrides, matching every actual embedding request. This resolves the pinned graph's dynamic attention reshapes: an ORT trace showed one CoreML partition with no CPU-provider nodes instead of 27 CoreML partitions and 54 CPU-provider nodes. Registration alone is not evidence of GPU/ANE use; the trace proves the execution provider, not Apple's internal hardware scheduling.

CoreML inputs and outputs are FP32, and low-precision GPU accumulation is explicitly disabled. Apple may still choose internal precision for its selected compute device; CoreML vectors are not promised bitwise equal to CPU. [CoreML provider options](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html) document this policy and compiled-model caching. Compiled graphs persist under `~/Library/Caches/eidolon/coreml/<model-sha256>/<environment-sha256>/<precision-and-shape-policy>`, independently of `model_dir`. The environment hash includes the loaded ORT build information (version, revision and flags) and the macOS build. Changed weights, runtime, OS build, or precision policy therefore cannot reuse stale compiled artifacts; deleting the cache requires compilation again. On macOS, `eidolon fetch-models` prepares automatic inference after verifying the weights, paying the first compilation cost before scanning.

If CoreML is needed and its cache is missing, incomplete, or invalidated by a new environment key, preparation emits `compiling model for this Mac, one-time, ~30s` on stderr. The estimate comes from the benchmark Mac and varies by hardware. A ready compiled package does not repeat the notice. Compilation failure does not stop automatic scans: CPU inference is retried with the warning above. `fetch-models` explicitly prepares CoreML independently of the current scan workload.

Embedding cache identities include preprocessing, the resolved provider, and precision/shape policy. Still-image inputs use `/imagenet-whole-squash224/v1/`; their cache reads cannot accept center-crop vectors. Frame matching retains `/imagenet-center224/v1/` and its existing qualified caches. CPU ends in `/cpu-ep-fp32/v2`, while CoreML uses `/coreml-mlprogram-fp32io-gpuaccum32-static1x3x224x224-all/v1`. Auto accepts either current provider-qualified identity for the selected use and writes only under the actual resolved provider; explicit CPU/CoreML requests accept only their own identity. Legacy unqualified entries and the former `/cpu-fp32` namespace remain intentionally missed because their provider policy was uncontrolled. Model weights and the static inference shape are unchanged.

`Embedder::{frame_model_id, frame_cache_model_ids, embed_frame}` select the center-crop policy. Video frames and 96-square still-image `FrameOf` descriptors use it. Before image matching, the CLI also loads a **source-aspect** center bank when embeddings and `--image-source-bank on` (the default) are enabled, and adds its cosine neighbors to the whole-image candidate union. `--image-source-bank off` skips bank preparation, bank inference-work accounting, and its additional candidates; whole-image matching and image-to-video retrieval remain enabled independently. This bank uses the still-image retrieval decode without the 96-square squash; it is not interchangeable with the image-to-video descriptor. The source bank is cached under `image.source-center/.../v1`, separately from whole-image and video descriptors. Bank preparation and image candidate/proof times are printed on stderr when the bank is requested. With the bank on, image-only scans and scans with thumbnails disabled compute both still-image retrieval embeddings, but not the image-to-video descriptor. All policies share one verified graph snapshot and inference pool.

### CPU embedding concurrency

`OnnxEmbedder::load_with_device(..., ExecutionDevice::Cpu)` verifies and retains the pinned 88.5 MB graph without creating sessions. The first cache miss initializes one CPU session. Extra sessions initialize only when concurrent inference exhausts the initialized sessions, up to `max(1, min(available_cpus / 2, 8))`. Serial calls reuse one session; a warm cache creates no session. Each session keeps two intra-op threads, one inter-op thread, sequential graph execution, and disabled intra/inter-op idle spinning. The pool releases its bookkeeping lock before construction/inference and returns reserved slots on errors or unwinding. Pooling does not change CPU preprocessing.

The cap bounds model/arena memory independently of caller count. Lazy sessions use the same immutable, SHA-verified snapshot even if the model path is replaced or removed; its read is capped at the pinned graph size plus one sentinel byte. The snapshot costs 84.4 MiB.

## Retrieval decoding and canonical proofs

Candidate hashes, ORB descriptors and embedding inputs use previews with a longest side of at most 800 pixels. Large lossy RGB/grayscale JPEGs use libjpeg-turbo's 1/2, 1/4 or 1/8 DCT decode when it can preserve that target resolution; unsupported scaling cases use the canonical decoder. On macOS, HEIF previews come from ImageIO's primary-image thumbnail decode with `CreateThumbnailFromImageAlways`: embedded thumbnails are ignored. Native HEIF orientation wins over redundant EXIF; EXIF-only orientation is applied once. ImageIO previews are rendered as white-composited sRGB. Reduced decoder output uses SIMD bilinear resizing for the 800-pixel input and 128-square retrieval hashes.

Reduced pixels are retrieval signals, never proof. Only candidate participants materialize the canonical full decode, decoded-pixel digest, Triangle-resampled pixel/structural previews and optional ICC-to-sRGB proof. A required full fallback decode is reused for its canonical proof and existing Triangle retrieval resampling, avoiding a second decode or resize. Proof dimensions and quality evidence retain the original oriented dimensions, not thumbnail dimensions. Public `decode` always returns the full canonical image.

Retrieval, ORB and embedding cache identities include the reduced-decoder policy, linked libjpeg-turbo version and, on macOS, the ImageIO OS build. Canonical full-decode proof entries have their own versioned key. A warm cache needs no image decode; a new candidate without a canonical proof triggers the full decode before verification.

A 12-native-photo, 144-file comparison retained all 132 original/derivative anchor pairs and precision 1.000, but reduced decoding lost three sibling edges and gained two (788/792 direct pairs versus 789/792 with full decoding), preserved identical duplicate groups, and improved cold CLI time only 1.72% (20.745 versus 21.108 seconds), below 5%.

## Signals, precision, and thresholds

1. **Candidate generation:** 64-bit DCT perceptual hash and gradient hash use exact multi-index Hamming range lookup, at most 14/64 and 12/64 respectively. Eight byte substrings probe nearby bucket keys, with a final full-hash popcount; no within-radius hash is lost at lookup. Complemented hashes also retrieve contrast-inverted versions. A 27-region pHash bank uses the same exact search at distance at most 20/64. Verification neighborhoods retain the best 64 full-frame neighbors and, independently, the best 48 same-dimension and 48 different-dimension region neighbors. Each neighborhood additionally retains its former exact-byte-eligible top-k, so newly retrieved close neighbors cannot evict an old candidate: at most 320 hash neighbors per image. Hashes operate on the 128-square retrieval thumbnail rather than repeatedly transforming full-resolution regions. Neural candidates remain the best 64 cosine neighbors at similarity at least 0.82. Lookup is exact; neighborhood caps still make final retrieval approximate and keep verification work linear in file count.
2. **Geometric proof:** ORB on a maximum-800-pixel long side: detect up to 4,000 points, then retain at most 20 per 8×8 grid cell (1,280 total). This prevents an added logo from consuming the entire descriptor budget. Mutual matches use Hamming distance at most 64 and Lowe ratio below 0.80. RANSAC requires at least 12 inliers, ratio at least 0.45, reprojection error at most 3.5 on normalized 800-unit coordinates, and spatial coverage of at least 4/16 grid cells. Full-frame corner drift is at most 1.5%; a crop must project convex bounds into 2.5–97% of the whole, with 3.5% border tolerance. Strict normalized full-frame pixel equality takes precedence over ambiguous repeated-pattern crop geometry. Rejected crop transforms may be refined from axis-aligned extent and unchanged-pixel-density seeds; non-improving refinements are discarded. RGB template refinement preserves the seed's aspect ratio and compares scale-matched RGB previews rather than fitting JPEG ringing by stretching the scene.

    Default bidirectional descriptor matching computes each 256-bit Hamming distance at most once while maintaining both images' two nearest neighbors. A partial distance at or above both current second-neighbor bounds stops immediately: remaining bits cannot change either nearest-neighbor result or its strict ratio test. Native-word descriptor views are derived once per image per run; the persisted ORB feature format is unchanged.

3. **Photometric proof:** aligned 128-square previews require at least 90% overlap, mean RGB absolute error at most 0.065, unchanged pixels at least 64%, and edge agreement at least 70%. Localized overlays may instead affect 0.3–25% of pixels: at least 90% of changed pixels must fit one rectangle covering no more than 24/64 preview blocks, leaving background mean error at most 0.030 and background edge agreement at least 90%. At least four background blocks must each contain two agreed scene edges; an empty background or a few coincident edges cannot prove an edit. This accepts opaque watermarks without mistaking unrelated scattered differences for an edit. A semantically close embedding or homography alone is insufficient.

    Duplicate photometric proof also checks the central 75% in a 6×6 grid. A cell is informative when either image has RGB RMS contrast of at least 0.02; half of these cells (rounded down) must have locally centered RGB correlation of at least 0.85. At least four cells must agree across two rows and two columns. Blank cells do not vote, and the overlay rectangle cannot hide changed informative cells from this check. Thus white space, a shared top bar, or a left navigation strip cannot independently prove an edited/reencoded page; a genuine small local edit retains agreement in the surrounding page content. This gate applies to crop, strict full-frame, and fast thumbnail proofs too; exact decoded equality remains independent.

    Exactly equal aligned RGB samples also support featureless reencodings. They never establish `SameContent`: that relation still requires the full decoded-pixel digest, including retained high-bit-depth values.

    When a contained source has a sharper effective preview resolution than its whole-image target, rejected pixel comparisons are retried at the mapped pixel density. This avoids treating resampling/JPEG ringing along sharp grid edges as unrelated content. A bounded quarter-preview-pixel translation search can remove the remaining sampling phase error after RGB registration. The same photometric, localization, edge, and overlap thresholds still apply; pixel evidence declares whether scale matching was used.

    Crop identity additionally requires average absolute signed channel bias outside the localized region of at most 1/255. JPEG and resampling noise may have large absolute error while canceling in this signed mean; a coherent colour or lighting shift does not. Embedded RGB ICC profiles supply an alternate sRGB-normalized preview, which must independently pass the same pixel, edge, localization, overlap, and bias gates. Raw previews remain available for stripped-profile copies. HEIF ICC metadata is read from the primary image handle because the image decoding hook does not expose it. No embedding or colour-profile exemption bypasses pixel verification.

    A candidate that passes ordinary pixel support but fails crop identity remains eligible for bounded geometric and sampling-phase refinement. Without ORB proof, an apparently localized residual between images whose pixel counts differ by more than 10% also needs crop registration before it can be called an overlay. This avoids treating a sparse resized crop as an edit, or discarding a low-quality JPEG crop solely because a noisy initial homography leaves a biased residual. Recompressed centered grid crops exercise this distinction without changing approximate candidate-retrieval thresholds.

4. **Keypoint failure:** ordinary ORB, pixel, overlay, and structural matches are verified first. A rejected candidate may first try one native-pixel-density registration, so repeated JPEG encodings cannot consume a crop's entire multi-scale budget. Impossible native-density shapes are skipped without template work. Only remaining rejected pairs compete for the more expensive 17-scale sweep: at most eight neighbors per image with fewer than 512 keypoints are eligible. Registration seeks three agreeing translation votes among nine patches at a fixed candidate scale; collinear patches are valid because no projective transform is being estimated here. RGB registration rejects near-uniform or color-incompatible inputs and requires trimmed error below 0.018, sampled on a 32-square grid to avoid repeated-pattern aliasing. Independent 128-square photometric verification remains mandatory. A structural registration pass can recover globally restyled crops. Both registration tiers are disabled by `no_keypoints`. Without geometric proof, ordinary duplicates require hash distance at most 10, mean error at most 0.025, unchanged at least 88%, and edge agreement at least 90%.
5. **Relation and confidence:** full decoded equality yields `SameContent`; verified containment yields `CropOf`; localized residuals yield `Edited` (including watermarks); small full-frame residuals yield `Reencoded`. Flat canvas padding preserves duplicate content and is classified by containment, not as a design version. Global recolours, light/dark versions, and re-lighting yield the related-but-not-duplicate `Variant`, not `Edited`. Global colour/lighting versions need aligned luminance/value/extrema correlation at least 0.92 and absolute signed-gradient correlation at least 0.84 with registered geometry, or 0.985/0.94 without it, plus nontrivial contrast and edge energy. The compared channels may be inverted, including a recolour combined with inversion. Colour/lighting changes must affect at least 35% of blocks with mean error above 0.035 and must not be a localized overlay. Other sufficiently verified pairs yield `Similar`. Scores are bounded to `[0,1]` and filtered using the caller's threshold. Equality keeps native high-bit-depth differences rather than treating 8-bit preview equality as pixel equality. Alpha is composited on white; invisible RGB channels are not matching evidence.

    Monotone nonlinear tone changes also compare histogram-rank-normalized channels, but only when both selected channels retain at least four bits of entropy. This prevents normalization from amplifying flat inputs into structural proof. Gradient-magnitude phase correlation independently establishes full-frame geometry when its response is at least 0.75 and displacement is at most half a pixel on the 64-square registration preview, overriding unreliable repeated-pattern ORB fits. Translated scene windows may use a response of 0.25 only to propose geometry: iterative overlap refinement, the same registered structural thresholds, and 50–93.75% sampled shared scene in both directions must confirm it. Each window must expose new scene, so ordinary containment is not a reframe.

    Structural proof must also be spatially distributed inside the central 75% of the image. A 4×4 interior grid needs at least six supporting cells across at least three rows and three columns; at least half of the non-flat cells must agree. Each supporting cell requires sign-consistent pixel correlation of at least 0.85 and gradient correlation of at least 0.65. This prevents a shared canvas border or checkerboard watermark from overwhelming different underlying photographs.

    Raw and rank-normalized pixel/gradient samples are derived once per image per run from the persisted preview. Identity comparisons reject failed global correlation, contrast, or gradient gates before computing interior support. Neither optimization relaxes any proof threshold.

    A geometrically contained pair that already passes crop-identity proof remains `CropOf`, even when distributed JPEG/resampling residuals cross the global-change threshold. Noise does not become a design version. An ORB fit that supports neither a full frame, a containment direction, nor a two-sided scene reframe is discarded as unusable, leaving independent registration available.

Hash range lookup is exact within its stated radii, but the bounded hash neighborhoods and embedding kNN are not exhaustive all-pairs candidate retrieval. Disabling embeddings reduces crop recall; disabling keypoints removes geometric crop proof. Very small or heavily altered overlaps can be intentionally rejected: this detector favors precision over calling two similar scenes or different pages of the same UI duplicates.

Versioned binary cache entries store visual hashes/previews, ORB coordinates/descriptors, and embeddings separately. Keypoint/embedding disable flags do not load or compute disabled features. Every reported pair includes raw signal values and explanatory notes plus per-member `quality` pixel-count evidence for the CLI's keep hint. Byte-identity reporting remains the CLI's exact stage.

### Retrieval coverage

Hash candidate monotonicity applies with fixed embeddings, not across preprocessing policies. Still-image matching uses both whole-image and source-aspect center-crop neighborhoods: source-center candidates retain the prior center-focused retrieval alongside the whole-image signal. Both banks are used independently of video presence and thumbnail matching; their union still requires the same pixel and geometric proof. Retrieval remains bounded, so neither bank promises exhaustive semantic neighbors.

Current independent-holdout limits are in the [root README](../../README.md#known-limits).

## Opt-in fast matching

`config.fast = true` (CLI `--fast`) uses a distributed 32×32 grid on the cached 128×128 RGB preview instead of examining all 126×126 interior pixels. The sampling density is a compile-time specialization of the same verifier, not a separate hash/embedding-only classifier. Both modes use the same ORB geometry, overlap, RGB error, signed colour bias, localized-overlay, structural, and ICC proof gates. Crop refinement and bounded fallback registration remain available.

Strict full-frame RGB or localized-overlay support can finish before ORB and phase work. All other candidates retain the shared geometric/structural verifier; a failed cheap proof is not itself a rejection. Higher `min_score` settings can still trigger ORB confirmation when it could raise an otherwise sufficient thumbnail match's score.

Fast ORB matching caches 32 inverted byte bands once per image per run. Each descriptor searches the twelve least-crowded bands, ignoring a band when it contains more than one eighth of the target descriptors. Retrieved pairs receive an exact 256-bit Hamming comparison. Sets with fewer than 16,384 possible pairs use exhaustive matching. This bounded retrieval avoids repetitive-band overhead; it is approximate and may miss correspondences. Mutual matching, distance/ratio limits, RANSAC, spatial coverage, and independent pixel/structural proof remain required. Default ORB matching remains exhaustive. Neither the byte index nor native-word views change the persistent feature format.

Borderline contained crops with at least 60% unchanged sampled pixels retry a failed sparse comparison at full cached-preview density. This recovers signed-colour-bias sampling errors in low-quality watermarked crops without weakening crop identity or overlay thresholds. Evidence distinguishes the ordinary 32×32 sample from this adaptive full-preview proof.

Every fast image match has `thumbnail` evidence containing aligned RGB MAE, unchanged/edge/background agreement, coverage, sampling density, and any scale/ICC normalization. Hashes and embeddings generate candidates but cannot independently establish a match. No proof-free image match is emitted, so these matches have no `unverified` marker and can contribute duplicate-group links. `SameContent` still requires the exact decoded-pixel digest, never sampled equality alone.

Feature extraction and versioned per-file cache formats are shared with default mode; toggling fast mode cannot leave a partially populated default feature entry. Disabled embeddings/keypoints remain disabled. Default matching and its proof density are unchanged. Both modes obey `min_score` and the same directional relation convention.

## Regression and timing commands

```sh
cargo clippy -p eidolon-image --all-targets -- -D warnings
cargo nextest run -p eidolon-image
# Offline CPU session/provider regressions; require the already-fetched model.
cargo nextest run -p eidolon-image --lib concurrent_embeddings_preserve_single_session_cpu_values --run-ignored only
cargo nextest run -p eidolon-image --lib cpu_provider_is_explicit_in_native_node_trace --run-ignored only
# Explicit network-capable acceptance: fetch into ~/Library/Caches/eidolon/models.
cargo nextest run -p eidolon-image --test relations --run-ignored only --success-output immediate
# No download here; measure the already-fetched model and cold/warm per-file extraction.
cargo nextest run -p eidolon-image --lib measures_real_feature_extraction_and_cache_hits --run-ignored only --success-output immediate
cargo nextest run -p eidolon-image --test runtime --run-ignored only --success-output immediate
cargo nextest run -p eidolon-image --test variants --run-ignored only --success-output immediate
cargo nextest run -p eidolon-image --test colour_pipeline --run-ignored only --success-output immediate
# Fast-mode evidence, cache-mode isolation, real ORB crop direction, and optional embeddings.
cargo nextest run -p eidolon-image --test contracts --run-ignored only --success-output immediate
# Optional offline stage/corpus profiling; requires the already-fetched model.
EIDOLON_IMAGE_BENCH_FILE=/path/to/photo.jpg cargo nextest run -p eidolon-image --lib profiles_feature_stages --run-ignored only --success-output immediate
# Compare full decode vs reduced retrieval hash Hamming distributions before scoring.
# Output must not exist; input may be one image or an image-only directory.
EIDOLON_IMAGE_EQ_INPUT=/path/to/images EIDOLON_IMAGE_EQ_OUTPUT=evaluation/hash-equivalence.json cargo nextest run -p eidolon-image --lib profiles_reduced_hash_equivalence --run-ignored only --success-output immediate
EIDOLON_IMAGE_BENCH_INPUT=/path/to/image-directory cargo nextest run --release -p eidolon-image --lib profiles_generated_image_corpus --run-ignored only --success-output immediate
# Candidate generation only, with a previously warmed feature database.
EIDOLON_IMAGE_BENCH_INPUT=/path/to/image-directory EIDOLON_IMAGE_BENCH_CACHE=/path/to/features.sqlite EIDOLON_IMAGE_BENCH_RETRIEVAL_ONLY=1 cargo nextest run --release -p eidolon-image --lib profiles_generated_image_corpus --run-ignored only --success-output immediate
```

The standalone runtime regression removes Cargo's runtime-library environment in four fresh processes. Explicit CPU fallback and missing-library checks retain a 15-second deadline. Default Auto gets an empty isolated compiled cache with a 90-second deadline, then a second process must reuse that ready cache within 15 seconds without a compilation notice. The Auto cases require the actual CoreML provider and embed a decoded desktop photograph, so CPU fallback cannot falsely satisfy the cache checks.

The photo tests use `sips` to convert real macOS desktop photographs into isolated temporary directories. They assert JPEG quality-30 resizing, 60%-area and modest crops with correct direction, semitransparent and opaque watermarks, cropped JPEG-quality-25 watermarks, low-texture containment even among 16 already-matching encodings, unrelated photographs, warm-cache determinism, score filtering, and disabled embeddings. Global recolour, relighting, dark, combined inversion/recolour, and native Grid Magenta versions distinguish `Variant` from crops and overlays, on textured photographs and smooth graphics, with and without the fetched model. Flat-canvas controls, including partial-source containment, remain duplicate crops. Additional generated decoded inputs cover all raster formats, alpha, high-bit-depth equality, shared-chrome UI rejection even across themes, cache invalidation, missing/corrupt models, JPEG/HEIF orientation precedence, and linear candidate/registration budgets. No copyrighted system photograph is checked into the crate.

Crop-identity controls compare genuinely decoded light/dark grids and require that they never become `CropOf`. Colour-pipeline controls preserve crop direction across Display P3-to-sRGB conversion, stripped ICC metadata, a PNG gamma chunk, different JPEG encoders with 4:2:0 chroma, high-saturation JPEG quality 25, and saturated P3 conversion through both PNG and HEIC. They run in default and fast modes, both with embeddings disabled and with the fetched model; profile-normalized evidence identifies the cases that require actual colour conversion.

Spatial-proof regressions compare real unrelated photographs with identical canvas or checkerboard decorations, unrelated textured foregrounds on almost-empty backgrounds, off-center broad-gradient crops, and independently encoded same-ridge recolours within a crowded JPEG cohort. They exercise the public detector without embeddings; valid recolours remain `Variant` while decoration-only matches are rejected.

Generated screenshot regressions use identical top bars, left navigation, and white canvases with different interior content. They must not match in default or fast mode; a small local edit to the same generated page must remain `Edited`. No private screenshot fixture is retained.

Current independent-holdout limits are in the [root README](../../README.md#known-limits).
