# eidolon-eval

Local-only ground-truth corpus generation and pair-level evaluation. No detector implementation or core deserialization changes are needed.

```sh
cargo run -p eidolon-eval -- generate ./eval-small --scale small
cargo run -p eidolon-eval -- score ./eval-small/truth.json report.json --json
cargo run -p eidolon-eval -- run ./eval-small --eidolon target/release/eidolon
cargo run -p eidolon-eval -- run ./eval-medium --scale medium --fail-under 0.80
cargo run -p eidolon-eval -- run ./eval-small --json -- --fast --video-fps 0.5 --embed-device cpu
```

## Generation

Requires macOS desktop pictures, `sips`, `man`, Homebrew-installed license texts, `ffmpeg` with libx264/lavfi, and `ffprobe`. No network calls or downloads occur. A destination must be empty; existing data is never overwritten by `generate`. Failed generation retains its partial directory for inspection.

Small contains 228 media files: six originals of each kind, with 132 images (including video thumbnails), 48 texts, and 48 videos. Medium contains 2,280 files: sixty originals of each kind, with 1,320 images, 480 texts, and 480 videos. The expanded totals include explicit design versions, subtle duplicate color changes, padded canvases, and three video-thumbnail scenarios. Source captures live separately under `sources/`, detector inputs under `media/`. `truth.json` contains every media pathname and hash, original-to-derivative duplicate relations/directions, decoded-visibility-qualified design versions, source provenance, and true hard negatives. Original local sources and unnormalized manual-command stdout are retained before transformation.

- Images: converted desktop JPEG scenes (maximum dimension 960), with the original taking the leftmost 75-percent-width window. Derivatives include byte copies, half-size JPEGs, 320-pixel q70 thumbnails, q25 JPEGs, lossless JPEG-to-PNG, PNG-to-JPEG, random-offset crops of 80/60/40 percent **area**, visible checkerboard watermarks, combined crop/logo/q25, and 90-percent-size copies on a padded canvas. `subtle_hue` and `subtle_relight` remain **duplicate** positives with measured decoded RGB change at most 11/255. Separate non-duplicate versions use strong hue, light/dark, relighting, and a different right-hand scene window; reframing changes at least 25 percent of the window and is not a padded smaller copy.
- Texts: two distinct license texts plus independently selected manuals, byte copies, CRLF, rewrapping, contiguous 10/20/30-percent word excerpts, and approximately 2.3-percent word substitutions. Originals have at least 300 whitespace-delimited words, so the smallest excerpts contain at least thirty source words.
- Videos: seeded, independent Conway-life lavfi sequences and Ken-Burns desktop-picture pans. Originals are 80 seconds, 960×540, 8 fps; derivatives are byte copies, 90-kbit/s 360p, a ten-second clip starting at five seconds, a 20-second (25-percent) clip starting at forty seconds, visible box watermark, and letterboxing. A strongly hue-shifted whole video is a non-duplicate design version. Each original also produces a 320×180 q70 frame, a square frame with title-bar overlay, and a 1280×720 q85 poster. Their directional `frame_of` annotations include full-length duplicate videos and clips only when the sampled timestamp is inside the clip.

Default seed is fixed; `--seed <u64>` changes crop/excerpt offsets and lavfi seeds. Reproducibility assumes the same installed source assets and codec/tool versions. Sources are sorted deterministically, prioritizing two iMac colors, two different Big Sur photos, and two Grid colors to exercise source-design versions and real photographic negatives even at small scale. Full-size desktop assets take precedence over same-name thumbnails. Every generated image is opened, every video is probed, and every text is read; all SHA-256 hashes are verified before the manifest is written. Raw retained sources are outside the counted detector corpus.

Generation rejects cross-family text sources sharing fifteen consecutive normalized words **or** more than 0.1 Jaccard similarity of normalized five-word shingles. Normalization is NFKC, full Unicode case folding, NFKC, then alphanumeric/combining-mark tokenization. This deliberately catches shared license bodies even inside otherwise different documents. The fifteen-word limit applies to all text-family pairs, including hard negatives: only shorter common boilerplate remains. Rejected manual/license candidates are retained too; only accepted families enter `media/`.

Decoded desktop sources are filtered by normalized 64×64 RGB comparison, so renamed or resized/re-encoded copies cannot create negative families. Generated video provenance records the actual lavfi seed/parameters or Ken-Burns source. The final audit checks unique video parameters and compares 64×36 temporal RGB samples across every original-video pair. Image/video originals with mean channel difference at most 2/255 are rejected.

Visibly different same-source colors, light/dark treatments, relighting, and reframing are **related versions, not duplicates** (`relation: "variant"`) when their aligned decoded change reaches 20/255. Named collections identify candidate source-design hypotheses, not proof of a common 2D composition. This includes Grid, iMac, Mac, Motion, Radial, Light Stream, explicit Big Sur/Monterey/Ventura **Graphic** designs, Dome, Calibrate, Chroma and Hello Metallic. Photographic location prefixes do not merge independent photos: Big Sur Aerial and Big Sur Coastline remain different. Ken-Burns videos inherit their source-picture hypothesis.

Each strong synthetic version gets a separate `family` branch and shares its source `design` class. Variant truth requires complete same-kind scene windows and aligned decoded RGB mean absolute difference >=20/255. **Cross-source** links additionally require registration of the two decoded originals by rotation, uniform scale and translation: both normalized luminance and gradient correlation >=0.99, mutual overlap >=80%, luminance RMS contrast >=8/255 and gradient RMS >=1/255 per pixel. Aspect-preserving 32/64-pixel-long-edge thumbnails use a fixed coarse-to-fine search; no detector output influences registration. Failed or feature-poor registration means **unscored**, not unrelated: propagated pairs lose Variant positives, are not hard negatives, and predictions/groups on them are ignored through their shared design hypothesis. The gate applies to every named collection, including within-colour Chroma camera angles. Same-source synthetic derivatives need no cross-source registration. Other visibility/full-frame exclusions remain: crops, watermarks, padded copies and subtle changes do not become Variants. Ignored pairs count as `ignored_sibling_predictions`.

Every successful generation writes `distinctness.json` and prints its counts, maximum text shingle overlap, and zero-conflict audit result. The complete all-pairs source-family audit runs before `truth.json` is written; generation fails rather than publishing a leaking manifest. These media checks cover exact/near-identical sampled content, not a proof that different artistic originals are semantically unrelated.

`eidolon-eval refresh-truth <old-truth.json> <empty-metadata-dir>` reapplies registration, visibility and negative rules to retained media and reruns decoding, hashes and distinctness. It writes corrected `truth.json`, `distinctness.json`, `registration.json` and an annotation-refresh receipt; the manifest still points to the original media directory. `registration.json` retains each source-family transform, score, coverage and per-kind counts of unscored/removed-positive pairs. Refreshing annotations alone does not change whether a corpus is tuning or frozen. No media or prior manifest is rewritten. Duplicate edges, including strictly source-proven `frame_of` annotations, are preserved: a shared design hypothesis does not create FrameOf positives. Metadata writes are exclusive and output directories must be empty.

`eidolon-eval refresh-frames <old-truth.json> <empty-metadata-dir>` cheaply refreshes only still-video clip labels; it reads metadata, not media or detector output. Recorded Ken-Burns zoom/pan expressions determine the crop at every source frame time in a clip. Outside the thumbnail's timestamp, crop-window IoU >=0.8 certifies `frame_of`, 0.3..0.8 is unscored, and <0.3 is explicitly negative. Exact timestamp provenance remains valid, including center-square thumbnail crops. Native-video labels are unchanged. `frame-windows.json` records source coordinates, best frame times, overlaps and edge-change counts; generation and full truth refresh also apply this rule.

Low-overlap thumbnail/clip negatives carry `"direct_only": true` in `truth.json`: a direct match is a false positive, but grouping through their shared original video is correct and is not a group false positive. Other hard negatives forbid both direct matches and group connectivity; an omitted `direct_only` field defaults to `false`.

### Archived natural-source corpora

`eidolon-eval generate-sources <sources.json> <empty-out-dir> --seed <u64>` applies the same image/text/video transformation matrix to an explicit **offline** source manifest. It never downloads. The manifest contains `{"version":1,"sources":[...]}`; each source supplies `kind` (`image`, `video`, `text`), local `path`, `sha256`, `title`, `author`, `licence`, `licence_url`, original `source_url`, and local `raw_capture`. Optional `raw_sha256` also verifies the archived capture. Relative paths resolve against the input manifest. Accepted licences are Public domain, CC0 and CC BY 1.0/2.0/2.5/3.0/4.0; acquisition/licence evidence belongs in additional retained manifest fields. Text extraction must be declared as a derived representation, not raw HTTP.

For HTML text sources, extract the work's prose rather than site navigation or licence-banner UI. Exclude those containers structurally; do not remove matching phrases from ordinary prose. Keep licence evidence in the archived response and manifest. Shared licence/footer text still fails the unchanged cross-family fifteen-word-span gate.

The full source manifest and native source bytes are retained separately from detector inputs. Images are bounded to a 960-pixel scene before the standard scene-window/variant matrix. Native video originals and exact copies preserve bytes, extension, codec and GOP; H.264 derivatives are bounded to 960 pixels and 8 fps. Sources must be at least twelve seconds: ten-second and quarter-length clips use the actual duration, and thumbnail-to-clip truth uses those same intervals. An image/video ancestry link exists only when the retained provenance explicitly records `ffmpeg ken-burns source=...`; matching numeric indices never link independently acquired media. Cross-source registration, decoding/probing, SHA-256 and distinctness audits still gate `truth.json`.

## Scoring semantics

Paths are joined against `truth.root`; absolute CLI paths also work. Core FileIds are bare numbers; extra CLI fields are ignored. Missing CLI files remain in the recall denominator. Unknown paths, duplicate IDs/paths, dangling IDs, unknown relations, and invalid scores are errors.

Ground truth annotates original-to-derivative duplicate edges and complete design-version relationships. An unannotated pair of siblings is **excluded from precision**, because two crops/excerpts from one original need not overlap. This exclusion is reported as `ignored_sibling_predictions`; it is not a true positive. Unrelated cross-family pairs and explicit hard negatives are negatives. No similarity-score cutoff is applied by the scorer.

`overall` contains duplicate metrics only; `variants` contains separate non-duplicate version precision, recall, and label accuracy. Variant truth also has aggregate `image/variant` or `video/variant` category rows. A wrong-channel prediction is a miss in the expected channel and a false positive in the predicted channel: reporting a design version as a duplicate cannot improve duplicate recall. Variant matches never connect duplicate groups. The CLI's top-level `variants` projection is accepted but not counted again; `matches` is authoritative.

Direct recall requires an explicit match in the correct channel. Duplicate group recall uses connected components of non-variant direct matches and all reported groups, including overlapping groups. Group precision penalizes all connected non-duplicate pairs, including annotated design versions. Variant metrics have `group_expected: 0`; their group recall prints `n/a`. Duplicate false positives are attributed to each distinct endpoint transformation category; variant false positives use each endpoint kind's aggregate variant category. Category counts are not additive. Overall channel counts deduplicate unordered pairs. Repeated reports use the highest-confidence relation per channel; label accuracy uses the highest-confidence report across channels. A confidence tie uses the first report.

Relation accuracy is conditional on any direct prediction being present on an annotated pair, including a wrong-channel prediction. Direction accuracy is conditional on an annotated directional pair receiving a direct prediction, and requires both the expected label and part-before-whole order. Group-only finds do not invent a relation or direction. Missing accuracy denominators serialize as `null`; empty precision denominators yield 1 and empty recall denominators yield 0 in JSON. Human output prints recall as `n/a` when its denominator is empty, including `original` rows and variant group columns.

Human and JSON reports include duplicate and variant metrics, kind/variant categories, top twenty misses, direct misses, direct and group false positives, and wrong directions. Direct false positives are ranked by descending confidence; other lists follow deterministic manifest/path order. `--fail-under <0..1>` gates **duplicate overall group recall**, excluding variant positives; it exits 2 below threshold without changing the JSON shape. Low scores otherwise exit successfully; malformed inputs and tool errors exit 1.

`run` reuses an existing `truth.json` (its scale/seed take precedence), otherwise generates. It passes only `media/` to `eidolon --json`, retains stdout as `eidolon-output.json` and stderr as `eidolon-stderr.txt` before parsing, then scores. Default detector resolution is workspace `target/release/eidolon`, otherwise `cargo run --release -p eidolon-cli --`. An explicit `--eidolon` path is used as supplied. Repeated runs replace only these two evaluator-owned report captures, never corpus files.

Options after the final `--` are passed directly to eidolon as separate argv values, not through a shell. The runner explicitly enables `--thumbnails on` for comparable local and URL `FrameOf` metrics; override it with `-- --thumbnails off` or `-- --thumbnails=auto`. Extra options such as `--fast`, `--video-fps`, and `--embed-device` are otherwise unchanged. The JSON report and saved `eidolon-score.json` record effective detector options in `eidolon_args`; standalone `score` omits this field because no detector was invoked. Both `--option value` and `--option=value` forms override managed defaults, including URL `--remote-video-mode`.

## URL evaluation

`eidolon-eval serve <corpus-or-truth.json> --port 8787` serves manifest-listed media over **loopback only**. It supports HEAD, GET, suffix/open-ended/single byte ranges, ETag, Last-Modified, Content-Range, and `/__eidolon__/stats`. Ctrl-C writes `url-traffic.json`. Only media-body bytes are counted, not HTTP headers or statistics responses; interrupted clients do not terminate the server.

`eidolon-eval run <out_dir> --urls --remote-video-mode keyframes --json` deterministically selects exactly one fifth (rounded down) of non-original images and videos separately. When that budget covers all transformation categories, it first reserves the lowest seeded SHA-256 pathname per category, then fills remaining slots by the same hash rank. This guarantees real remote clip and thumbnail denominators without increasing the 20-percent budget. Originals and all text stay local. Mixed inputs use `eidolon --stdin --null`. `--remote-video-mode full-cadence` forwards the alternative sampling policy; the report records the selected mode. Omitted mode means explicit `keyframes`.

`url_traffic` reports **client-consumed** body bytes from CLI URL provenance against each reported remote object's known size, including cache-hit objects with zero new bytes. If any reported artifact size is unknown, client URL traffic metrics are omitted rather than printing a numeric ratio from an incomplete total. `served_traffic` independently reports loopback body writes for the selected URL sample; TCP buffering can make this exceed client-consumed bytes. CLI provenance supplies no request count, so those counters are `null`, not invented. Standalone `score --traffic url-traffic.json` attaches server counters without replacing client counters.

JSON includes `input_transport` recall by `local|remote|missing` × kind × variant, and `frame_of` recall by local/remote/missing **video target**, plus thumbnail category. Missing output files remain misses; no unobserved frame is assumed found. These are actual relation recalls, separate from source-frame availability. Frame/group metrics use duplicate connectivity; Variant predictions never connect groups. Copy reports before repeating a run if comparing sampling modes: evaluator-owned stdout/stderr captures are replaced.

## Final frozen holdout7 evaluation (2026-10-29)

Holdout7 was scored once in the designated final evaluation, with one cold local scan and one cold mixed-URL scan. It contains 760 source-disjoint natural-source files (440 images, 160 texts, 160 videos), 870 duplicate pairs including 330 `frame_of` pairs, 877 Variant pairs and thirty hard negatives. Image/video sources are licensed Wikimedia Commons works; text sources are public-domain works. No threshold was tuned from these results.

| Metric | Local | Mixed URL (`keyframes`) |
| --- | ---: | ---: |
| Duplicate direct precision / recall | 1.000 / 0.907 | 1.000 / 0.841 |
| Duplicate group precision / recall | 1.000 / 0.974 | 1.000 / 0.929 |
| Variant precision / recall | 0.999 / 0.806 | 1.000 / 0.811 |
| All local-video `frame_of`, direct / group | 262/330 / 309/330 | 211/267 / 250/267 |
| Remote-video `frame_of`, direct / group | n/a | 14/63 / 33/63 |
| Cold scan wall time | 417.73 s | 332.21 s |

Local overlay-thumbnail direct/group recall is 54/110 (0.491) / 99/110 (0.900); remote-video overlay recall is 2/21 (0.095) / 11/21 (0.524). Group connectivity can depend on another clean frame of the same video being present; it does not establish direct overlay proof. Local video Variant recall is 0.367. The mixed run consumed 135,857,173 / 338,674,709 remote body bytes (0.4011) across 112 remote files.
